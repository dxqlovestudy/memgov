## 二、逐篇可抄的算法

### 2.1 MEMOIR §3.3 Certified Temporal Supersession（最直接可落地）

这一步就是「何时该标取代」的可执行判定：

1. 候选生成：按时间排序，新项 `m_n` 与旧项 `m_o` 的 **cosine ≥ 0.85**（只要话题重叠），再用轻量词法矛盾检测器 `TRIAGE-α` 给冲突信号 `w_conf`。相似度只用来筛候选，**不单独作为判据**。
2. 三视角判官：对同一对候选分别问「直接替换」「时间优先」「对抗兼容」，每个判官只回 `SUPERSEDES` 或 `INDEPENDENT`。
3. 接受条件：`SUPERSEDES` 票数占比 > **τ_s = 0.6**。
4. 动作：旧项标 `retired`（**不物理删除**），新项保留指向两条源记录的链接；可回滚。
5. 边界：这是可选算子，作者明确它改变的是"有效内容"而不是"压缩"，因此与 merge 分开记账。

对 memgov 的落点：现在的 supersede 只认 `metadata.supersedes`，而写入侧从来不打这个标 —— 正好用这套判定**补标**，而不是直接失效。

### 2.2 CALM §3.2 / §3.3 生命周期图 + 查询门控

- 生命周期图 `G_t = (M_t, E_conf, E_dep)`：冲突边与依赖边用**确定性规则**生成，不用模型打分。
- 冲突强度 ≥ **0.75** 才允许触发 supersession；弱冲突只记录、不替换任何一方。
- 依赖边方向是「前置记忆 → 依赖它的记忆」，命中规则即建边，不设全局阈值。
- 查询时对每条候选算四维向量：`[语义相关性 ζ, 有效性 V, 查询-记忆兼容性 ψ, 1−冲突风险 R]`，用固定策略（CALM-ZS）或可学习门控做准入。

对 memgov 的落点：现在只有 `valid / invalidated` 二值；改成「有效 + 历史可回溯」，并对弱冲突单列状态（记录但不失效），避免把"暂时存疑"直接判死。

### 2.3 LEDGER §III-C / §III-E 显式写规则 + 删除墓碑

写规则只有五条，按事件流顺序应用，核心两条：

- **restate**：同值（任意来源）→ 只加出处，并把 trust 取两者较高值，不产生新值。
- **supersede**：不同值且来源**至少同等可信** → 关闭当前条目、在其时间点开新条目；关掉的条目**仍能回答历史问题**。

两条前置防伪：① 输出 schema 只列本批事件 id，claim 不能引用不存在的事件；② Grounding check —— claim 的值必须在其事件原文里出现（忽略大小写与标点），挡掉编造值。

删除：受影响槽位擦除**包括历史值在内**的所有条目，保留不含值的墓碑；从未把擦除记录再喂给抽取器；之后用户重提该值才开新条目。

对 memgov 的落点：① 给 supersede 加"来源可信度"比较，来自低可信源的替换不自动生效；② `verify-forgetting` 应加一条"删除后证据回扫"，LEDGER 的判据是"被删值一次都不出现在证据里"，比我们现在只看召回复活的判据更严。

### 2.4 FGSE 写入侧门控（memgov 完全没有的那一半）

- 候选教训结构化：`precondition` / `behavior change` / `expected effect` / `verifier`。
- 只在**临时状态**应用，跑三类探针：target-transfer（迁移到别的任务是否仍成立）、falsification（构造反例能否推翻）、archived-regression（历史用例是否退化）。
- 按实测增益与风险决定 commit / refine / reject。
- 实测把有害提交压到 3.6%、回归损伤 1.3%。

对 memgov 的落点：memgov 是事后治理，只能"事后补标/失效"；若要做写入侧，应放在 Hermes 的 Hindsight 插件（写入链路），改动面比 memgov 大，需单独评估。

## 三、对 memgov 的差距表

| 能力 | memgov 现状 | 论文做法 | 差距性质 |
|---|---|---|---|
| 取代判定 | 只认显式 `metadata.supersedes` / tag | MEMOIR 三判官投票 + 词法冲突信号；CALM 冲突强度阈值 0.75 | 缺判定算法 |
| 取代标记来源 | 写入侧不打标，实际 0 命中 | LEDGER 用显式规则在摄取时决定当前值 | 缺上游输入 |
| 冲突分级 | 只有 valid / invalidated | CALM 强冲突才替换、弱冲突记录 | 缺状态 |
| 去重 | 精确重复 + bigram 相似度 0.95 | MEMOIR 合并前 preservation screen，验收口径是"审计 0 损失" | 缺无损证明 |
| 删除后验证 | verify-forgetting 只看召回是否复活 | LEDGER 回扫证据，要求被删值 0 出现 | 判据偏弱 |
| 写入侧门控 | 无 | FGSE 三类探针 | 完全缺失 |
| 来源可信度 | 无 | LEDGER trust 比较 | 完全缺失 |

## 四、可执行的改造清单（按收益排序）

1. **补取代标记（不改写入链路）**：新增「候选对 → 三判官 → 写 `metadata.supersedes`」的离线步骤，参数取论文值：候选 cosine ≥ 0.85、接受票比 > 0.6、证据必须原文子串、confidence ≥ 0.90。写完不直接失效，交给现有 supersede 策略在下一轮执行 —— 保持"显式标记才动"的硬规矩。
2. **冲突分级**：在 models 里加 `weak_conflict` 状态，强度 0.60~0.75 只记录不失效。
3. **去重加无损证明**：近重复合并前做 preservation screen，验收按「审计 N 次合并 0 损失 + 损失率上界」报数。
4. **verify-forgetting 加证据回扫**：除召回复活外，统计"被删值是否仍出现在任何注入证据里"。
