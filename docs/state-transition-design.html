记忆状态迁移治理 · 总设计

一条新事实宣告「VM 联调环境已下线」之后，所有「VM 仍是当前入口 / 位于 VM / 在役」的旧断言应该一起失效。现有 memgov 处理不了这种一对多的状态迁移；本设计补上这一层。

摘要 一句话结论

问题不是「AI 判错」，而是「AI 没机会判」。旧事实写 IP、新事实写域名，没有共同锚点，文本相似度也不够——现有两两配对根本不会把它们放在一起。状态迁移需要按“实体 scope”反查，而不是按相似度找。
现有能力
显式取代 / 重复 / 两两冲突

ttl、supersede、dedup、importance、scope_limit 与 ai-govern。

缺口
一对多状态迁移

一条迁移事实应让多条旧断言一起过时，现有流程没有这个方向。

新增
ai-transition

迁移识别 → scope 反查 → transition-v1 判官 → 失效 / 历史标记。

二、根因 为什么现有治理抓不到

原因说明
一对多，不是两两一条迁移事实应影响多条旧断言；现有 ai-govern 只做 pair。
实体不同名旧事实写 IP 172.20.12.116，新事实写域名 agent-dev.jlpay.com，没有共同锚点。
文本相似度低「位于 aether-vm」与「已下线、统一走 dev」的 bigram 重叠不足。
跨来源旧事实 document_id=None（迁移自 WeKnora），新事实在当前会话文档；按会话缩小会漏。
状态无生命周期Hindsight 只有 valid/invalidated；召回按相关度排序，不按时间判新旧。
朴素正则不可用：对 5,607 条有效事实按「下线/停用/迁移 + VM/1092143/IP/入口」匹配，得到 2,748 条候选旧事实，会误杀 Hindsight 服务、Wi-Fi、端口约定等无关事实。必须 scope 收窄 + AI 判官。

三、目标与非目标

目标

1. 识别状态迁移并绑定 scope。

2. 按 scope 反查旧「当前状态断言」，不依赖相似度。

3. 专用 AI 判官区分「当前已过时」与「历史记录」。

4. 全自动失效、可回滚、可回查、可审计。

5. 对现有规则策略零侵入，复用 adapter / ledger / verify / rollback。

非目标

1. 不判断记忆内容真假。

2. 不删除任何记录（只失效）。

3. 不替换召回排序或 re-ranker。

4. 不在写入侧做同步拦截（第一阶段仍是批量扫描）。

5. 第一阶段不处理阈值/次数类口径修订。

五、处理流水线 八步

读快照全部 valid 的 world/experience，记录时间与 document_id。
识别迁移事实正则初筛迁移动词，AI 分类器确认，排除否定/假设句。
抽取 scope受控实体词典 + 锚点 + 别名归一，不做通用分词。
scope 反查同 canonical_id、时间早于 T 的旧事实；不看相似度。
状态断言过滤旧事实需含当前状态措辞；纯历史措辞单独标记。
AI 判官transition-v1，一对 T→A，输出 verdict + 双方原文引用。
机器闸门schema、证据子串、置信度、时间、authority、上限。
执行与回查只失效；写台账；召回回查；F>10% 自动回滚。
执行前重读：apply 前重新读 A 的 state / updated_at，若已被改过则跳过并告警，避免快照过期误杀。

六、候选扩展 scope 驱动，不是相似度驱动

# 伪代码
for T in detect_transitions(valid_facts)[:max_transitions]:
    for S in T.scope_entities:
        olds = entity_index[S.canonical_id].older_than(T)
        olds = [A for A in olds if A.state == valid and has_state_marker(A.text)]
        ranked = rank(olds, key=(same_entity_type, shared_scope_count, recency))
        for A in ranked[:max_candidates_per_transition]:
            v = judge_transition(T, A)       # transition-v1
            if gate(v) and v.verdict == "obsolete_current":
                actions.append(invalidate(A, reason=f"state_transition:{T.id}"))
参数默认作用
max_transitions20单轮迁移事实上限
max_candidates_per_transition30单条迁移的旧断言上限
max_invalidations10（首周 3）爆炸半径
confidence0.90状态迁移误杀代价更高
max_judgements200总判官调用成本上限

七、判定契约与提示词 transition-v1

# system prompt（核心段）
你是记忆状态迁移裁判（transition-v1）。

输入：一条迁移事实 T（较新）和一条旧断言 A（较早）。
任务：判断 A 的"当前状态"是否已被 T 废止。

定义：
- obsolete_current：A 把某实体描述为当前入口/在用/位于/可访问/有效，
  而 T 宣告同一实体已下线/停用/迁移/改名/不再使用。
- historical_ok：A 明确是历史记录（带具体过去时间、"当时/实测/此前/曾"），
  或描述的是不受 T 影响的属性（如主机仍存在、其他服务仍在运行）。
- unrelated：实体或属性不同，或 T 没有覆盖 A。
- uncertain：证据不足。

硬规则：
1. 只依据 A/T 原文，不引入外部知识。
2. 必须引用 A 原文作为 evidence_old，引用 T 原文作为 evidence_transition。
3. 主机仍存在 ≠ 联调入口仍有效；服务仍运行 ≠ 旧入口仍可用。
4. 带明确过去时间且语义为历史记录的，判 historical_ok。
5. 不确定判 uncertain；只输出 JSON。

输出 schema

{
  "verdict": "obsolete_current | historical_ok | unrelated | uncertain",
  "scope_entity": "host:aether-vm",
  "confidence": 0.0,
  "evidence_old": "<A 原文连续片段>",
  "evidence_transition": "<T 原文连续片段>",
  "historical_markers": ["当时", "2026-11-12 实测"],
  "reason": "<= 80 字"
}

动作矩阵

verdict置信度动作
obsolete_current≥ 0.90失效 A；reason=state_transition:<T.id>；replacement=T.id
obsolete_current< 0.90不动作；记 low_confidence
historical_ok任意不失效；可选打 status:historical + valid_until
unrelated / uncertain任意不动作
带 authority:official任意不自动失效；记 authority_conflict

八、安全与自动回滚

闸门规则
只失效不删除所有动作是 invalidate，可 PATCH state=valid 回滚。
证据evidence_old / evidence_transition 必须是原文连续子串。
时间只允许失效早于 T 的事实。
authority旧事实带 authority:official 时不自动失效。
并发apply 前重读 state/updated_at；变化则跳过并告警。
注入原文含「忽略以上指令 / system prompt」时跳过该对。
上限transitions / candidates / invalidations / judgements 四重上限。
回查失效后再召回；同 id 或近似原文命中即失败。
自动回滚F > 0.10 时恢复本轮全部失效。
审计run JSON + ledger.jsonl，含 T、A、scope、verdict、confidence、evidence、model、prompt 版本。

九、与现有模块的关系 复用，不重写

模块处理
adapters/复用；Hindsight 仍只暴露 world/experience。
ai.py 的 schema/证据校验、缓存、token 统计复用。
ledger.py 的 run JSON、rollback、verify_forgetting复用。
ai_governor.py 的 apply + auto-rollback复用。
transitions.py新增：迁移识别、scope 抽取、别名归一、候选扩展。
prompts.py新增 transition-v1（与 conflict-v1 并存）。
ai.py新增 transition decision 解析与动作转换。
ai_governor.py新增 TransitionGovernor。
cli.py新增 memgov ai-transition。
不修改现有 ttl / supersede / dedup / importance / scope_limit 的行为。

十三、风险与边界

风险缓解
误杀仍成立的旧事实（VM 主机仍存在）状态断言过滤 + transition-v1 + 置信度 0.90 + 回查回滚
别名漏配导致抓不到别名表评审；未命中只报告，不动作
历史证据丢失推荐 A；historical_ok 打 status:historical
候选爆炸scope 索引 + 三重上限；2,748 条朴素候选已证明不可用
模型判错证据子串闸门只能防编造；首周人工抽检 run JSON
快照非事务apply 前重读 state/updated_at
口径修订类（阈值/次数）第二阶段单独设计，不混入本流程
