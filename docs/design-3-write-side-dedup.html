改造 3 设计稿：写入侧重复治理

1. 结论摘要

  • 做什么：给 memgov 增加「增量去重」能力——每 5 分钟处理最近 10 分钟新增的 facts，用「embedding 近邻 + 数字/ID 签名」判定重复，命中即软失效。
  • 不做什么：不改 Hermes 写入插件、不动改造 1 的取代判官、不启用硬删、不做 observation 层治理。
  • 最大风险：cron 滞后 5 分钟，这 5 分钟内的重复仍会参与召回；误判靠台账 + rollback 兜底。

2. 问题与证据

证据数值采集方式
每天新增 facts约 330 条11-22 全天 created_at 统计
新增中重复占比62%42 对候选判官结果
全库 cos≥0.92 重复1,135 对 / 622 条 / 153 簇11,548 条全量 embedding
最大重复簇92 条「Multica 身份声明，仅 issue ID 不同」簇内抽样 12 条
现有清扫速度28 条 / 次今天 scan --apply 实测
产生 vs 清扫330 / 天 vs 28 / 次差一个数量级

现有机制为什么不够：

  1. dedup 策略是字面 bigram Jaccard，在 20 对人工金标上 0/8 命中（换词就掉分）。
  2. ai-supersede 的候选池上限 60 对，全库 1,041 条含冲突词记录，配不齐。
  3. 两者都靠人工触发，没有定时机制。

3. 目标与非目标

目标非目标
新写入的重复在 10 分钟内被清除追求 0 延迟拦截（那要改插件，见方案 A）
拦截率 ≥95%，误判率 ≤1%不做 observation 层治理（负收益已实测）
完全复用现有台账 / 回滚 / 回查机制不改改造 1 的判定逻辑
不改对话关键路径不引入新的 LLM 依赖（先只用确定性比对）

4. 数据模型

4.1 新增实体

实体字段说明
EmbeddingIndexids: str[]、vectors: float32[n,1024]、sig: str[]npz 落盘，支持增量 append
DedupCandidatenew_id、old_id、cos、sig_match、verdict候选对
IncrementalRunwindow_start/end、scanned、candidates、actions每次运行报告

4.2 状态机（复用现有）

valid ──(cos≥0.92 且签名一致)──> invalidated
  ↑                                    │
  └──────── rollback ──────────────────┘

4.3 签名定义

token_re = r"[0-9a-f]{8,}|\d+\.\d+|\d+"
sig(text) = tuple(sorted(set(token_re.findall(text))))   # 数字/ID 集合

为什么加这条：observation 层实测 673 个簇里，325 个（48%）是因为数字/ID 不同而误判（如「issue ID 为 01a1c487」vs「01a1c34b」cos=1.000）。sig 不同一律不判重复。

5. 流水线

步输入动作输出失败处理
1库内 updated_at ≥ now-10min 的 valid 记录拉增量new[]拉取失败 → 本轮跳过，记 warning
2new[] 文本取 embedding（缓存优先）向量API 失败 → 重试 3 次，仍失败则本轮跳过
3向量 + 全量索引余弦 KNN（cos ≥ 0.92）候选对索引缺失 → 触发全量重建
4候选对签名比对（sig 必须相等）过滤后候选—
5候选对生成 Action(invalidate, policy=dedup)动作—
6动作dry-run 只记账；apply 则 PATCH台账单条失败继续，记 error
7run 文件60 分钟后回查 state验证结果失败率 >10% → 告警

8. 动作矩阵与安全闸门

条件动作可逆
cos ≥ 0.92 且 sig 相等且 state=validinvalidate(old_id) + 台账✅
cos 0.85–0.92仅记录，不动作—
sig 不等仅记录—
记录属于最近 1 分钟内写入跳过（避免与新写入竞争）—
单轮动作 > 50 条中止并告警（防索引错乱导致批量误删）—

闸门：

  • --apply + MEMGOV_ALLOW_WRITE=1 双开关。
  • 每轮上限 50 条（max_actions）。
  • 台账 before 快照必填。
  • 回滚：memgov rollback runs/<run_id>.json --apply。

9. 验收

9.1 必须命中的正例

样本判据
92 条 Multica 声明簇（同 issue ID 的变体）应清到 1 条
「该次机检的结果为 GATE\exit=0\red=0\report=reply.md」同簇 12 条应清到 1 条
「状态板当前没有进行中事项」同簇 12 条应清到 1 条

9.2 必须保留的反例

样本判据
「issue ID 为 01a1c487」vs「01a1c34b」（cos=1.000）必须不动作（签名不同）
「白名单两条」vs「白名单三条」（不同属性）必须不动作
「模板ID可重复」vs「模板ID必填」必须不动作（属性不同）

指标目标命令
