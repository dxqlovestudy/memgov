数据面

控制面
memgov

读快照、判去留、发失效/恢复、记账、回查；不在每轮对话路径上。

观测面

质量、延迟、库健康、遗忘失败率；只读，不参与治理决策。

一、结论摘要

三条硬边界：① memgov 不在每轮对话路径上，对话写入/召回由 Hermes 插件直接打 Hindsight；② memgov 不存记忆、不做召回排序；③ 所有写动作可逆，只 invalidate，restore 即回滚。
层角色一句话
数据面Hindsight存文档、事实、observation；提供 recall；pg0 持久化。
控制面memgov批量治理：规则策略 + AI 判官 + 机器闸门 + 执行 + 台账 + 回查。
观测面看板 + 评估 + Phoenix只读结果：质量、延迟、库健康、F 率；Phoenix 可选。

五、数据流 四条链路

1. 对话写入（实时）

用户 → Hermes Agent → Hindsight 插件 sync_turn → Hindsight POST /memories（document_id=session）→ 抽取 facts / 生成 observations。

2. 对话召回（实时）

Hermes Agent → 插件 prefetch → 先无条件注入 profile:dxq → Hindsight recall → 过滤 <0.65 → 记忆块进 system context。

3. 治理运行（批处理）

cron/CLI → memgov 读快照 → 规则策略/候选 → AI 判官 → 机器闸门 → dry-run 或 PATCH invalidated → 回查 F → 失败回滚 → ledger。

4. 观测（定时）

Hindsight logs/stats + 本机 agent.log → VM collect.py → memory_dashboard.py；27 题 eval → 看板 → boards 页面。

八、失败模式与保障

失败检测处理
召回慢/断连24h p90、取消数、recall failed看板标红；不改召回链路
retain 未可见prefetch timeout 计数看板显示；治理不依赖最新一轮
治理判错证据子串、置信度、keep-newer、authority拒绝动作
失效不生效verify-forgetting F 率超阈值自动回滚
并发写apply 前重读 state/updated_at跳过并告警
候选爆炸scope 索引 + 四重上限停手并报告
